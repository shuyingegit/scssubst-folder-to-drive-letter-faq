Map a local folder to a Windows drive letter without copying

Short answer: map the folder to a drive letter so deep paths become short, with no file copy involved.

ScsSubst is a small GUI around the built-in Windows subst command.

Does it copy the files?

No. subst Z: D:\projects\my-thing creates a second name for an existing local folder: Z:\ and D:\projects\my-thing\ are the same bytes on the same disk. Delete one and you delete the other.

Does the letter survive a reboot or a log-off?

No. A subst mapping lives in the Windows session that created it, so it is gone at log-off and gone after a reboot. Two consequences bite in practice:

  • A service or scheduled task running as the system account will not see Z:, because system work runs in Session 0 — and a mapping created by a scheduled task is invisible to your desktop session.
  • ScsSubst keeps the list of mappings and can re-apply them at start-up, so your letters come back when you sign in again — not at boot, and not for Session 0 services.

Administrator rights? A driver?

Neither is needed. subst is part of Windows, works with an ordinary user account, and uses plain Windows APIs — there is no file-system driver involved at all.

Can it map a network share?

No. subst maps a path on a local drive; a UNC path is not a valid target. For a NAS or file server you want a client that actually mounts the remote side as a local disk — see drive.scsoi.com.

Limitations worth knowing

  • Local folders only — no UNC, no network shares.
  • The mapping is per-session, as described above.
  • Some tools resolve the underlying path again (when they display the real folder), so the shorter path is not always visible.
  • No permissions, encryption or quotas are added; the mapping exposes the folder under a second name, nothing more.

Why bother?

The classic reason is a deep path you keep typing: D:\work\clients\2026\acme\project\.... The other one I care about is isolating workspaces: give each project (or each agent) its own letter so tools that only accept a drive root have something to point at.
