# FAQ：给本地文件夹一个独立盘符（Windows）

`subst` 是那种「本来只解决一个小问题、解决得非常好、然后在某个地方突然坑你一次」的内置命令。下面是我被问到的问题，以及我希望当初有人先告诉我的答案。先做利益披露：ScsSubst 是我们做的（https://subst.scsoi.com/），所以提到产品的地方请当成有倾向；`subst` 本身的行为是微软的，不是我们的。

## 它会复制文件吗？

不会。`subst Z: D:\projects\my-thing` 不复制、不移动、也不生成副本，只是给已有的本地文件夹起了第二个名字，`Z:\` 和 `D:\projects\my-thing\` 是同一份数据、同一块盘。删掉一边，另一边也没了。如果你以为它会生成一份独立副本，那是用错工具了。

## 盘符重启或注销之后还在吗？

不在——这是最容易搞错的地方。`subst` 映射属于**创建它的那个 Windows 会话**。注销就没了，重启也没了。

由此带来的实际影响：跑在系统账号下的服务或计划任务看不到 `Z:`，哪怕你的桌面会话里还挂着它——系统级工作跑在 Session 0。反过来也一样，计划任务建的映射在你的桌面会话里同样不存在。

ScsSubst 会保存映射清单，并支持在启动时重新应用，所以盘符会在**你再次登录**时回来——不是开机时，也不是给 Session 0 的服务用。

## 需要管理员权限吗？会装驱动吗？

都不用。`subst` 是 Windows 自带的，普通用户账号就能用，走的是纯 Windows API——完全不涉及文件系统驱动，没有内核组件，不用装任何东西。

## 能映射网络共享吗？

不能。`subst` 映射的是本地盘上的路径，UNC 路径不是合法目标。如果你想要盘符的那个文件夹在 NAS 或文件服务器上，`subst` 是错工具——那需要真正把远端挂上来的客户端（比如 https://drive.scsoi.com/ 这个把 WebDAV/NAS 挂成真实本地磁盘的客户端）。

## 它真正的限制有哪些？

- 只能映射本地文件夹，不能 UNC、不能网络共享。
- 映射是会话级的，如上。
- 盘符本质是给「认盘符的工具」用的便利。有些程序会自己解析回真实路径（比如在界面上显示实际文件夹时），所以「路径变短」不一定处处可见。
- 映射不带来任何权限、加密或配额，它只是把同一个文件夹换个名字露出来。

## 我到底为什么想要这个？

最经典的理由是那串永远敲不完的深层路径：`D:\work\clients\2026\acme\project\...`，一个盘符就省了手。另一个我在意的理由是隔离工作区：给每个项目（或者每个 agent）一个独立盘符，那些只接受盘符根目录的工具就有东西可指。
